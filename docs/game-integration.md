# 游戏接入

[返回项目说明](../README.md)

## 目录归属

游戏源码、素材和依赖统一放在 `web-vue/games/`，并在浏览器中运行。Java 游戏使用 CheerpJ，原生网页游戏直接加载站内网页。平台后端管理账户、游戏资料和游玩记录。

每个游戏使用一份 `game.json`。构建工具根据配置生成游戏文件和网页清单。共用运行器源码位于 `web-vue/games/runtime/web/`，主题参数位于 `web-vue/src/styles/tokens.css`，发布文件由构建工具生成。

## 导入游戏包

开发者在 `web-vue` 目录执行以下命令：

```powershell
npm run games:import -- D:/Games/MyGame
npm run games:build
```

游戏包目录需要包含 `game.json`，开发者也可以单独指定配置文件：

```powershell
npm run games:import -- D:/Games/MyGame D:/Games/my-game.json
```

导入工具会检查游戏编号、路径、依赖和文件体积，再复制配置声明的文件并更新 `web-vue/games/registry.json`。如果编号已存在，工具会保留原有工程。

## 原生网页入口

原生网页游戏将 `runtime` 设为 `html5`，用 `entry` 声明发布后的 HTML 地址，用 `build.web` 声明网页源码目录。构建工具使用 Vite 打包脚本、样式和素材，发布到该游戏的 `runtime/`。原生游戏使用 `/games/native-player.html`，加载前核对购买权限，就绪后开始计时，关闭时停止游戏并保存记录。目前原生入口只启用通用游玩计时，不提供编辑器、导入、导出或自定义关卡事件。

`entry` 固定为 `runtime/index.html`，网页源码目录提供 `index.html`，相对图片、样式和脚本由 Vite 生成内容指纹。

## 普通 Java 入口

Swing 或 AWT 游戏提供 `public static void main(String[] arguments)` 后，即可使用普通入口：

```json
{
  "id": "puzzle",
  "name": "拼图",
  "runtime": "java17",
  "mainClass": "puzzle.Main",
  "classpath": ["game.jar"],
  "arguments": ["{assets}"],
  "cover": "assets/cover.png",
  "build": {
    "source": "src/main/java",
    "cover": "cover.png",
    "libraries": []
  }
}
```

`build.source` 指定源码目录。已有 JAR 的游戏可以改用 `"jar": "binary/original.jar"`。两种方式都使用共用 Java 运行器，游戏规则仍由 Java 代码实现。

依赖项填写在 `build.libraries` 中，并在 `classpath` 中列出游戏和依赖文件。程序通过类路径读取音效或图片时，使用 `build.resources` 指定资源目录，构建工具会按原目录结构将资源放进 JAR。需要安装到用户目录的素材包时，配置 `build.assets` 和运行字段 `"assets": "assets.zip"`。

运行器会将 `{assets}` 和 `{data}` 替换为当前账户对应的游戏目录。依赖本机原生库、外部进程或专用渲染方式的游戏需要提供适配器。运行器支持 Java 17 字节码及其兼容版本。

## 可选能力

| 配置 | 用途 |
| :--- | :--- |
| `capabilities.editor` | 显示编辑器入口 |
| `editorMainClass`、`editorArguments` | 普通 Java 工程的编辑器类与参数 |
| `adapter` | 游戏专用浏览器适配器，使用后由它接收打开操作 |
| `capabilities.importData` | 显示数据导入，适配器负责业务校验 |
| `capabilities.exportData` | 显示数据导出，共用文件工具按配置目录打包 |
| `capabilities.gameplayEvents` | 适配器提供统一关卡事件，网页自动记时与结算 |
| `gameplay` | 服务器核对关卡使用的目录、文件前缀、奖励和时间字段 |
| `imports` | 导入编号范围、最大体积、文件类型和字段名称 |
| `dataDirectory` | 导出数据所在的相对目录，默认 `data` |
| `preservedPaths` | 素材升级时保留的用户目录，如 `levels`、`saves` |
| `display` | 虚拟桌面宽度与高度 |
| `build.licenses` | 发布时一并保留的许可文件 |
| `build.include` | 导入时同时复制的说明或附加文件 |

普通游戏可以省略可选能力，此时平台只显示开始入口。需要数据导入的游戏应提供适配器校验，并配置文件范围和体积上限。

专用适配器负责打开或关闭游戏，也可以按需提供数据导入和关卡事件能力。

启用关卡事件的游戏使用 `begin`、`heartbeat` 和 `finish` 上报会话、游玩时间与关卡结果。平台会按顺序处理事件，并为正式关卡结算奖励。试玩和自定义关卡可以保存记录，但奖励为零。

普通 Java 入口可以省略关卡事件，平台会记录游戏运行时间，并在打开编辑器时暂停计时。游戏需要通关记录和奖励时，应启用相应能力；服务器会根据本地发布配置核对关卡。

平台在导航区域保留游戏运行窗口。用户切换站内页面时，游戏会继续运行；返回游戏可以接着使用当前实例。关闭游戏、退出账户或刷新浏览器后，平台会结束当前实例。

共用文件工具 `platform.runtime.GameFiles` 负责安装素材、导出文件和写入文本，各游戏适配器负责处理具体文件格式。

## 植物大战僵尸

商城封面位于 `web-vue/games/pvz/media/menu.png`，使用主菜单截图。商品介绍简要说明游戏玩法。

用户购买后可以从商城或游戏库启动游戏。正式关卡奖励规则见[字块币与游戏商城](blockcoin.md)。

游戏库将封面、介绍、启动、收藏和编辑器入口放在同一条目中。植物大战僵尸包含六个关卡、图鉴和 Swing 编辑器。游戏画面沿用平台导航和标题栏，并按原始尺寸显示。

在主菜单点击冒险模式或图鉴后，网页先显示加载层。Java 在后台准备关卡封面或图鉴首屏资源，并回传进度。百分比按约 15 秒的节奏递增，以已完成的进度为上限。资源准备完成后，加载层最多显示到 99%，目标页面绘制完成后直接进入。

在选关页双击关卡封面即可进入。第一关的顶部卡槽在选卡和战斗中都显示四格。选满后再点一张可选卡会提示「卡槽已满」。第二关预选的四张指定卡带有锁图标，点击时提示「本关指定卡片，不能更换」。

战斗中点击右上角的「菜单」可暂停，然后选择「继续游戏」或「重新开始本关」。暂停时间不计入游玩记录。重新开始会放弃当前对局并重新加载同一关，普通关卡会重新进入选卡。

网页和游戏内的“关卡编辑器”入口会打开同一个编辑器。编辑器与游戏共用运行环境，管理员可使用该功能，普通用户无法使用。

游戏使用 `levels` 作为数据目录，关卡编号范围为 0–99。编辑器支持导入、导出和保存关卡，数据按账户分别存储。管理员可以在「系统管理 → 游戏资料管理」维护名称、介绍和奖励。移除游戏登记只会删除数据库中的登记和关联记录。

## 美式八球

第二款游戏源码位于 `web-vue/games/billiards/web/`，商城入口仍为 `/games/billiards/game.json`。游戏使用 Canvas、JavaScript 和 Matter.js，浏览器不加载 CheerpJ。台面按原逻辑坐标绘制，状态区使用 HTML，小屏按可用宽度缩放台面，文字与操作区单独换行。重复打开会恢复当前对局，关闭时停止动画循环并释放音频环境。

八球入口按职责分成输入与循环、电脑回合控制、界面状态更新三个模块，测试位于同级 `tests/`。平台共用运行协议留在 `games/runtime/`，服务端判罚与奖励结算留在 Java 后端。

游戏提供单人电脑对抗和本地双人模式，每盘由服务器随机确定先手。电脑根据遮挡、切球角度和袋口选择路线，使用有限次物理预演挑选力度，再加入小幅瞄准和力度误差。电脑可自动摆放自由球，电脑回合不接收人类击球输入。

游戏保留开球、定组、自由球、8 号球胜负判定，以及开门红、一杆双收、一杆三收、连下三城、翻袋好球和勾球进袋六项成就。开门红只表示合法开球进球，球台此时仍开放，之后首次普通合法进球才定组。成就奖励 1–11 字块币，单人击败电脑另奖 20，具体条件见[字块币规则](blockcoin.md)。

原生运行器通过现有游玩会话转交台球事件，开盘收到服务端确认后才开始操作。每杆报告带相同盘号和递增序号，服务端保存球组、轮次和待结算奖励，分出胜负后合并为一笔入账；重试保持原盘号与原序号。中途重开或退出的未完成对局不结算。`billiards_round` 表由后端启动时按增量脚本建立，相关后端更新需要重启生效。

球台、球体 PNG 和音效位于 `web/assets/`，构建时随网页发布。商城封面来自实际游戏画面，音频来源与第三方许可分别保留在 `AUDIO-SOURCE.txt` 和 `MATTER-LICENSE.txt`。独立 Java 版继续在原桌面工程维护，平台不再保存 Java 迁移参考副本。

原生版沿用原项目的尺寸、摩擦和恢复系数，碰撞求解器改为 Matter.js，运行结果不保证与 Java 版逐位相同。固定物理步和运动子步防止高速球穿透，静止画面不重复绘制。滑动摩擦会同时改变球心速度与水平旋转，进入滚动后使用较小的滚动阻力。

后端启动时会根据发布注册表补齐缺失的商城条目，已有商品按入口匹配，管理员维护的名称、介绍和账户归属保持原值。

## 检查与发布

```powershell
npm run lint
npm run lint:comments
npm test
npm run games:test
npm run build
```

`games:test` 会构建全部游戏并执行 Java 游戏配置的检查。`npm test` 同时验证原生台球的真实物理、规则、成就和原生入口选择。植物大战僵尸的检查涵盖关卡、浏览器导入和共用文件工具。

用户首次运行 Java 游戏时，网页需要联网加载 CheerpJ。美式八球只加载站内资源。游戏页面和游戏包会保留所需署名与许可。

网页会自动加载运行环境和游戏包，用户可以直接从平台启动游戏。加载失败时，页面会显示对应阶段和原因。
