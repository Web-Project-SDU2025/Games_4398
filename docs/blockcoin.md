# 字块币与游戏商城

[返回项目说明](../README.md)

字块币（Blockcoin）是平台内使用的整数货币。账户首次使用商城时获得 100 字块币。植物大战僵尸售价为 100 字块币，用户每次完成一个官方关卡可获得 15 字块币，重新挑战同一关卡也可以获得奖励。

用户可以在商城中搜索游戏、按分类或持有状态筛选商品，并查看最近二十笔收支。用户确认购买后，游戏会持续保留在游戏库中，收藏状态可随时调整。

管理员可以使用关卡编辑器制作和试玩关卡。后端根据发布包中的关卡指纹核对正式奖励，编辑器试玩使用独立流程。

## 记账规则

后端决定金额、商品价格和奖励数额，客户端提交游戏编号和本局尝试编号。后端为初始发放、购买和奖励分别生成业务编号，同一请求重复提交时只记账一次。处理资金变动时，后端先锁定当前账户行，再通过同一事务更新余额、游戏归属和流水。

游戏开局后，通过 `/api/gameplay/begin` 上报独立会话编号、游戏入口、模式和关卡文件摘要。后端核对持有关系与请求频率后，返回本局挑战码，并根据服务器发布配置保存本局奖励规则。

游戏通过 `/api/gameplay/heartbeat` 定期提交累计有效毫秒数。服务器按实际经过时间限制增加量，并同步保存游玩记录。通过、失败、返回选关或关闭游戏时，网页通过 `/api/gameplay/finish` 保存最终结果。正式通关的记录与奖励在同一事务中提交，重试同一会话会返回原结果。

服务器从各游戏 `game.json` 的 `gameplay` 配置读取奖励、关卡目录和计时字段，再从本地素材包计算官方文件摘要。普通 Java main 游戏使用同一接口记录可见运行时长；需要关卡结果的游戏通过适配器提供事件。试玩和自定义关卡保留游玩记录，奖励为零。

通关结果由浏览器内的 Java 游戏上报。当前校验覆盖持有关系、关卡文件、会话时间和重复结算；服务器保存资金账本，客户端保存游戏过程。

网络请求失败时，网页会在当前游戏实例中使用原编号重试。正常关闭游戏前，平台会等待最后一批事件保存。浏览器强制退出或长期断网时，服务器保留最近一次心跳的时长，并在会话超时后将其显示为未通过。用户可以在游戏库的字块币足迹中查看结算结果。切换账户后，页面会清空旧余额，并读取新账户的数据。

管理员可以在“字块币收支管理”中按账户、收入或支出、原因和日期分页查询流水，表内保留每笔交易后的余额。账户页也提供对应账户的流水入口。查询直接读取现有账本，账户删除后仍保留其历史流水和账户编号。

管理员在“账户管理”中选择“调整字块币”，填写发放或收回的整数数量与原因。后端核对管理员身份、锁定目标账户，并同时保存余额与流水。流水包含操作人的账号和调整原因。收回数量最多为该账户的当前余额，发放后的余额上限为 20 亿字块币。网页重试时沿用同一操作编号，后端返回原操作结果。

“查看游戏库”显示目标账户当前持有的游戏。管理员填写撤回原因并确认后，后端记录操作人、目标账户、游戏和时间，移除对应归属，并将该游戏正在运行的会话标为已撤回。撤回不退款，购买流水、收藏与历史记录继续保留。旧购买记录和恢复接口都按有效撤回状态判断权限。用户重新购买时会支付一笔新的费用，原撤回记录保留并标记重新购买时间。

个人和管理员记录列表中的“隐藏”只保存当前账户的显示选择。原分数、时长、关卡结果和奖励继续保留，首页仍按完整记录统计游玩活动，“最近游玩”沿用相同的隐藏选择。后端在完整记录上附加 `hidden` 标记，记录列表使用同一筛选函数，其他账户分别读取自己的隐藏选择。

用户勾选“显示隐藏记录”后，可以找到已隐藏条目并选择“恢复显示”。隐藏和恢复共用账户权限校验，操作只改变当前查看账户的显示选择。

字块币初始发放、购买、通关奖励和管理员调整成功后，平台会在同一事务中发送账户通知。新账户创建、个人资料或角色变更，以及管理员撤回游戏时，相关账户也会收到通知。消息中心中的公告对所有账户可见，各账户分别保存自己的已读状态。顶部消息图标每三十秒轮询未读数量，页面隐藏期间暂停请求，消息正文进入消息中心后再分页读取。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `BlockcoinRules.java` | 初始余额、价格、奖励、会话与流水限制 |
| `BlockcoinService.java` | 账户锁、购买、归属、余额调整与奖励事务 |
| `AdminGameLibraryService.java`、`GameRevocation.java` | 管理员查看游戏库、撤回归属与操作记录 |
| `RecordVisibilityService.java`、`RecordVisibility.java` | 按查看账户保存记录列表的隐藏选择 |
| `MessageService.java`、`SiteMessage.java`、`MessageReceipt.java` | 账户通知、公告和个人已读回执 |
| `MessageRules.java` | 公告长度、发布间隔和消息查询上限 |
| `MessageTests.java` | 接收范围、回执、公告重试与管理员权限 |
| `GameplayService.java`、`GamePlay.java` | 通用会话、有效时长、关卡结果与幂等结算 |
| `GameplayRules.java` | 计时间隔、并发、过期和协议参数 |
| `AdminBlockcoinService.java` | 管理员流水筛选、分页与累计收支 |
| `AdminQueryRules.java` | 管理查询的分页、搜索和日期参数 |
| `BlockcoinManage.vue` | 按账户筛选和分页查看收支 |
| `BlockcoinAdjustment.vue`、`AccountGameLibrary.vue` | 账户资金调整与游戏撤回确认 |
| `BlockcoinHistory.vue`、`blockcoin-history.css` | 游戏库中的字块币足迹与独立样式 |
| `Messages.vue`、`MessageBell.vue` | 消息收件箱、筛选分页与未读提示 |
| `AnnouncementComposer.vue` | 管理员发布公告并保留失败重试 |
| `OfficialLevelCatalog.java` | 发布素材包中的官方关卡指纹 |
| `BlockcoinSetup.java` | 复用现有数据源执行增量表初始化 |
| `blockcoin-schema.sql` | 资金、会话与撤回记录的增量表 |
| `GameStore.vue`、`store.css` | 商城布局、筛选、购买确认和收支展示 |
| `stores/wallet.js` | 账户隔离的余额与商城状态 |
| `game-economy.mjs` | 运行身份与商品授权请求 |
| `game-play.mjs` | 通用事件队列、计时、重试与关闭保存 |
| `BrowserGameplay.java` | Java 游戏中的开局、时长、通过与失败事件 |

记账功能使用 `blockcoin_wallet` 和 `blockcoin_entry`，通用会话使用 `game_play`，撤回操作使用 `game_revocation`，游玩时长继续写入 `game_record`，记录显示选择使用 `record_visibility`，消息正文与已读状态分别写入 `site_message` 和 `message_receipt`。历史表 `reward_run` 保留已有数据。后端启动时会通过现有增量脚本创建缺少的表，并沿用原账户、密码、游戏资料和服务器连接配置。
