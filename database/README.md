# 游戏管理数据库

项目使用课程分配的数据库 `java_1_02`。前后端在本机运行，数据库位于线上，连接配置保持不变。

`../web-db.sql` 是迁移后的数据库导出文件，包含当前表结构、账号和菜单。导入前请先选中目标数据库。

完整导出文件和 `backups/` 只保存在本机。公开仓库中的 `schema.sql` 提供空表结构，`seed.sql` 提供角色和菜单，供初始化空数据库使用。向已有数据库重复导入可能影响现有数据。

`backups/before_game_migration.sql` 保存游戏迁移前的完整数据库和示例数据，可用于恢复旧版本。

当前在线数据库已执行 `migrate_game.sql`。该脚本会删除旧表中的示例数据和字段，只适用于已备份的旧结构；请勿在当前数据库重复执行。

| 表 | 内容 |
| --- | --- |
| user | 登录账号、密码、角色、个人资料、头像、签名以及游戏关联 |
| user_type | 管理员和游戏用户两种角色 |
| game | 全站游戏信息 |
| user_game | 每个账户的游戏库 |
| game_favorite | 每个账户的收藏 |
| game_record | 每次游玩的分数、时长和时间 |
| blockcoin_wallet | 当前账户的字块币余额 |
| blockcoin_entry | 初始发放、购买、奖励与管理员调整的唯一业务流水 |
| reward_run | 正式关卡尝试、挑战码与已领取状态 |
| game_play | 通用游戏会话、有效时长、关卡结果与已发奖励 |
| billiards_round | 每盘台球的模式、随机先手、轮次、球组、击球序号及奖励去重状态 |
| game_revocation | 管理员游戏撤回、操作人、原因与重新购买时间 |
| record_visibility | 每个查看账户隐藏的记录编号与操作时间 |
| site_message | 账户通知、公告和问题反馈正文 |
| message_receipt | 每个账户的消息已读时间 |
| feedback_resolution | 管理员对反馈的处理决定、回复和更新时间 |

后端通过 `blockcoin-schema.sql` 创建字块币相关增量表，并保留已有表和记录。资金规则见[字块币说明](../docs/blockcoin.md)。

后端启动时会为旧 `game` 表补齐可空字段 `level_reward`，用于保存管理员配置的通关奖励。空值沿用发布配置，显式 0 表示停发通关奖励；已有资料和流水不会被覆盖。此更新需要重启后端生效。

`game_play` 保存自动游戏会话，`game_record` 继续保存游玩时长和时间。旧记录与资金流水保持不变。

`billiards_round` 通过游玩会话隔离账户，并保存台球单盘的判定状态。每次成就或单人获胜收入使用独立业务编号写入 `blockcoin_entry`，网络重试不重复发奖。后端启动时会创建此增量表。

`game_revocation` 保存管理员撤回游戏的记录。撤回不会改变原购买流水或余额，用户重新购买后会留下新的购买记录。管理员调整余额使用现有钱包和流水表。

`record_visibility` 保存各账户的记录隐藏选择。隐藏不会修改 `game_record`、`game_play` 或字块币流水，首页统计仍使用完整记录。

`site_message` 保存账户通知、公告和问题反馈，`message_receipt` 分别记录各账户的已读状态。账户变更通知会与对应业务修改一并保存。

`feedback_resolution` 保存管理员对问题反馈的处理状态和回复。

新版本会保留现有账户、游戏和游玩记录。后端启动时会读取已发布游戏清单，按入口补齐植物大战僵尸和美式八球等商品，已有商品资料保持原值。

后端使用 `User` 表示管理员和游戏用户，使用 `Game` 和 `GameRecord` 保存游戏及游玩记录。账户接口通过 `userId` 传递编号，地址沿用 `/api/gameUser`。

`backups/before_user_merge.sql` 保存账户合并前的完整备份。当前数据库已完成账户合并，旧表清理脚本仅适用于迁移流程。

备份中保留一条未关联登录账户的个人资料。现有账户继续使用原编号、密码哈希和角色。

业务接口使用 POST。除登录请求外，请求体采用 `{"data": {...}}` 格式，成功码为 `0`。
