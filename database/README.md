# 游戏管理数据库

当前数据库为课程分配的 `java_1_02`。项目仍按本地前后端、在线数据库的方式运行，连接配置没有改变。

`../web-db.sql` 是迁移后的数据库导出文件，包含当前表结构、账号和菜单。导入时需要先选中目标数据库。

完整导出和 `backups/` 仅留在本机，不提交 GitHub。公开仓库使用 `schema.sql` 提供无数据的表结构，`seed.sql` 提供角色和菜单。二者用于新建的空数据库，不要在已有库重复导入。

`backups/before_game_migration.sql` 是修改前的完整备份，保留原有示例数据。它用于恢复旧版本，不是当前程序的初始化文件。

`migrate_game.sql` 已在当前在线数据库执行过一次，不能再次执行。脚本包含删除旧表示例数据和字段的操作，只能用于备份后的旧结构。

| 表 | 内容 |
| --- | --- |
| user | 登录账号、密码、角色、个人资料、头像、签名以及游戏关联 |
| user_type | 管理员和游戏用户两种角色 |
| game | 全站游戏信息 |
| user_game | 每个账户的游戏库 |
| game_favorite | 每个账户的收藏 |
| game_record | 每次游玩的分数、时长和时间 |

现有三个账号和密码保留。游戏和记录表暂时为空，没有把原来的示例内容当成游戏数据。

后端使用 `User` 统一表示管理员和游戏用户，不再保留 `Person`、`GameUser` 实体。游戏仍使用 `Game`，记录使用 `GameRecord`。账户接口的请求和返回编号统一为 `userId`，接口地址 `/api/gameUser` 保持不变。Vue 中的游戏列表、游戏库和收藏共用 `views/game/GameList.vue`，账户页面位于 `views/account`。

`backups/before_user_merge.sql` 是合并账户前的完整备份。`merge_user.sql` 负责复制资料并切换外键，逐字段核对成功后才执行 `finish_user_merge.sql` 删除旧表。这两个脚本也已执行，不能重复运行。

原来没有登录账号关联的那条个人资料保存在备份中，没有替它创建新账号。现有账号的编号、密码哈希和角色均保留。

接口仍使用 POST，请求体为 `{"data": {...}}`，业务成功码为 `0`。登录接口沿用最外层账号密码格式，不套 `data`。
